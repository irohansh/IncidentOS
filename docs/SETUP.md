# IncidentOS — Setup Guide

## Go-live checklist (follow in order)

1. `npm run setup:env` — copies `.env.example` → `.env` and generates random tokens for every `__GENERATE__` placeholder.
2. Fill every `CHANGE_ME` value in `.env` using the table below.
3. `npm run user:add -- <name>` — prompts for a password, prints `name:hash`. Paste into `DASHBOARD_USERS`. Repeat for each approver; add their names to `APPROVER_USERS`.
4. `npm run migrate` — applies all migrations to your Postgres database.
5. Start services with `EXECUTION_MODE=dry_run` (default). Commands are policy-checked but not executed; every step is labelled `dry_run`.
6. Configure your alert senders (see section below).
7. Send the curl test alert and verify a Slack thread appears and the dashboard shows the incident.
8. After a staged dry-run passes end-to-end, consider `EXECUTION_MODE=real` with a least-privilege kubeconfig.

## Where each secret comes from

| Variable | Where to get it |
|---|---|
| `ANTHROPIC_API_KEY` | [Anthropic Console](https://console.anthropic.com) → API Keys |
| `DATABASE_URL` | Your Postgres / Neon connection string (`postgresql://user:pass@host/db?sslmode=require`) |
| `DATABASE_URL_DIRECT` | Non-pooled URL — required on Neon pooler for migrations; leave empty otherwise |
| `PAGERDUTY_WEBHOOK_SECRET` | PagerDuty → Integrations → Generic Webhooks (v3) → New subscription → copy the signing secret (shown once) |
| `GRAFANA_WEBHOOK_TOKEN` | Generated by `setup:env`; paste the same value into the Grafana webhook contact point's Authorization header field |
| `ALERTMANAGER_WEBHOOK_TOKEN` | Generated by `setup:env`; paste into `http_config.authorization.credentials` in `alertmanager.yml` |
| `CUSTOM_WEBHOOK_TOKEN` | Generated by `setup:env`; use in `Authorization: Bearer <token>` for curl / custom senders |
| `GITHUB_TOKEN` | GitHub → Settings → Developer settings → Fine-grained PAT; repositories: your code repos + issues repo; permissions: Issues R/W, Contents R, Deployments R, Metadata R |
| `SLACK_BOT_TOKEN` | Slack app → OAuth & Permissions → `chat:write` scope → install → copy bot token (`xoxb-…`) |
| `SLACK_SIGNING_SECRET` | Slack app → Basic Information → Signing Secret |
| `PAGERDUTY_API_TOKEN` | PagerDuty → API Access Keys (read/write) |
| `PAGERDUTY_FROM_EMAIL` | A real PagerDuty user email (required by the notes API) |
| `PAGERDUTY_ESCALATION_ROUTING_KEY` | PagerDuty → Services → your escalation service → Integrations → Events API v2 → integration key |
| `PROMETHEUS_URL` | Your Prometheus instance URL (e.g. `https://prometheus.internal`) |
| `GRAFANA_URL` | Your Grafana instance URL |
| `GRAFANA_API_KEY` | Grafana → Service Accounts → new account with Viewer role → new token |
| `SESSION_SECRET` | Generated by `setup:env` (32 bytes base64url); never share |
| `DASHBOARD_USERS` | Output of `npm run user:add` — format `name:$2b$...hash` |
| `APPROVER_USERS` | Comma-separated names from `DASHBOARD_USERS` who may approve steps |
| `KUBECONFIG_PATH` | Path to a kubeconfig for a least-privilege service account (see RBAC example below) |

## Configuring alert senders

### Grafana
1. Alerting → Contact points → New → type **Webhook**
2. URL: `${PUBLIC_WEBHOOK_URL}/webhook/grafana`
3. HTTP Method: POST
4. Authorization header: scheme `Bearer`, credentials = `GRAFANA_WEBHOOK_TOKEN`
5. Add the contact point to the notification policy for your alert rules.

### PagerDuty
1. Integrations → Generic Webhooks (v3) → Add Webhook
2. Webhook URL: `${PUBLIC_WEBHOOK_URL}/webhook/pagerduty`
3. Scope: select the services you want to monitor
4. Events: `incident.triggered`, `incident.acknowledged`, `incident.resolved`
5. Copy the signing secret into `PAGERDUTY_WEBHOOK_SECRET`.

### Alertmanager
```yaml
receivers:
  - name: incidentos
    webhook_configs:
      - url: ${PUBLIC_WEBHOOK_URL}/webhook/alertmanager
        send_resolved: true
        http_config:
          authorization:
            type: Bearer
            credentials: <ALERTMANAGER_WEBHOOK_TOKEN>
```

### Slack app
1. Create app at [api.slack.com/apps](https://api.slack.com/apps)
2. Add scope `chat:write` under OAuth & Permissions → Bot Token Scopes
3. Install the app to your workspace and copy the bot token
4. Under Basic Information → Signing Secret, copy the signing secret
5. Under Interactivity & Shortcuts → enable, set Request URL to `${PUBLIC_WEBHOOK_URL}/slack/interactions`
6. Invite the bot to your incident channel: `/invite @<botname>`

## Kubernetes RBAC (least-privilege service account)

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: incidentos
  namespace: prod
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: incidentos
  namespace: prod
rules:
  - apiGroups: ["apps"]
    resources: ["deployments", "replicasets"]
    verbs: ["get", "list", "watch", "update", "patch"]
  - apiGroups: [""]
    resources: ["pods", "pods/log", "services", "endpoints"]
    verbs: ["get", "list", "watch", "delete"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: incidentos
  namespace: prod
subjects:
  - kind: ServiceAccount
    name: incidentos
    namespace: prod
roleRef:
  kind: Role
  name: incidentos
  apiGroup: rbac.authorization.k8s.io
```

Export the kubeconfig for this service account and set `KUBECONFIG_PATH` to its path. Set `ALLOWED_K8S_NAMESPACES=prod` (or your namespace list).

## First dry-run walkthrough

```bash
# 1. Start all services
docker compose --profile local up -d
npm run start:webhook &
npm run start:worker &
npm run dashboard &

# 2. Send a test alert
curl -X POST "http://localhost:3000/webhook/custom" \
  -H "Authorization: Bearer $CUSTOM_WEBHOOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "incident_id": "INC-DEMO-001",
    "title": "P1: checkout-api error rate > 20%",
    "alert_source": "custom",
    "affected_services": ["checkout-api"],
    "started_at": "'"$(date -u +%Y-%m-%dT%H:%M:%SZ)"'",
    "raw": {}
  }'

# 3. Open the dashboard at http://localhost:3001
# 4. Wait for triage + root cause + runbook to complete (~60-120 s)
# 5. Approve the first step in the dashboard
# 6. Confirm the step runs in dry_run mode and the postmortem is generated
```

## Running with Docker Compose

```bash
# Start all services (uses Neon — skips local postgres/migrate if DATABASE_URL is set)
docker compose up --build

# Verify no service runs as root
docker compose ps -q | xargs -I{} docker exec {} whoami
# All should print: node

# Run the test suite inside the builder image
docker compose --profile test run --rm test
```
